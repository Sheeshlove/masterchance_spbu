# Как поставить всё на сервер и обновлять данные без своего компьютера

Эта инструкция — про **Часть 2** из [КАК_ЗАПУСТИТЬ.md](КАК_ЗАПУСТИТЬ.md): как
сделать так, чтобы данные для приложения считались **сами, на отдельном
компьютере в интернете**, а ваш Mac был не нужен.

Написано максимально подробно. Если вы никогда не видели командную строку —
ничего страшного, просто копируйте команды по одной.

---

## Зачем вообще сервер

Чтобы приложение показывало шансы, кто-то должен:

1. скачать списки со всех направлений вуза (это сотни страниц);
2. прогнать **10 000 симуляций** конкурса;
3. выложить результат в интернет.

Это занимает от десятков минут до нескольких часов и требует, чтобы компьютер
всё это время был включён. Держать ради этого включённым свой Mac неудобно,
поэтому берём **сервер** — компьютер, который стоит в дата-центре и работает
круглосуточно. Настраиваем его один раз, дальше он всё делает сам по
расписанию.

> **Важно понимать сразу.** Сегодня работает путь **СПбПУ (Политех)**.
> Для СПбГУ готов разбор списков, но программы ещё не заносятся в базу
> автоматически, поэтому `--university=spbgu` пока данных не соберёт.

---

## Что вам понадобится

- банковская карта (сервер стоит примерно 300–700 ₽ в месяц);
- ваш Mac — только чтобы подключаться к серверу;
- аккаунт GitHub (у вас уже есть).

---

## Шаг 1. Возьмите сервер

Подойдёт любой хостинг виртуальных серверов (VPS). Например Timeweb, Selectel,
Beget, aeza — порядок действий у всех одинаковый.

При заказе выберите:

| Параметр | Что выбрать | Почему |
| --- | --- | --- |
| Операционная система | **Ubuntu 24.04** (или 22.04) | под неё написана инструкция |
| Оперативная память | **4 ГБ** | парсер запускает несколько браузеров сразу; на 2 ГБ он падает |
| Процессор | 2 ядра | симуляции считаются быстрее |
| Диск | **от 20 ГБ** | образ с браузером занимает около 1,5 ГБ |

После оплаты хостинг пришлёт письмо или покажет на экране три вещи —
**запишите их**:

- **IP-адрес** сервера (например `95.163.180.22`);
- **имя пользователя** (обычно `root`);
- **пароль**.

---

## Шаг 2. Подключитесь к серверу со своего Mac

1. Нажмите **⌘ + пробел**, наберите **Терминал** и нажмите Enter. Откроется
   окно с текстом — это и есть командная строка.
2. Наберите команду, подставив свой IP вместо `ВАШ_IP`:

   ```bash
   ssh root@ВАШ_IP
   ```

3. При самом первом подключении спросит:
   `Are you sure you want to continue connecting?` — наберите **yes** и Enter.
4. Спросит пароль. Наберите его и нажмите Enter.
   **Пароль не отображается — ни точками, ни звёздочками.** Это нормально,
   просто печатайте вслепую.

Если в начале строки появилось что-то вроде `root@server:~#` — вы внутри
сервера. Дальше **все команды выполняются здесь**, в этом же окне.

> **Как вернуться позже?** Открыть Терминал и снова выполнить `ssh root@ВАШ_IP`.
> Чтобы выйти с сервера — команда `exit`.

---

## Шаг 3. Установите Docker

Docker — программа, которая ставит всё нужное (Python, браузер, библиотеки)
одним куском, чтобы вы не устанавливали это по частям.

Скопируйте и выполните **одну команду целиком**:

```bash
curl -fsSL https://get.docker.com | sh
```

Побегут строчки — это нормально, ждите. Проверьте, что получилось:

```bash
docker --version
```

Должно ответить что-то вроде `Docker version 27.3.1`. Если ответило — идём
дальше.

---

## Шаг 4. Скачайте проект на сервер

```bash
apt update && apt install -y git
git clone https://github.com/Sheeshlove/masterchance_spbu.git
cd masterchance_spbu
```

Последняя команда «входит» в папку проекта. Проверить, что вы там:

```bash
ls
```

Должны увидеть список файлов: `bot.py`, `desktop.py`, `README.md` и другие.

---

## Шаг 5. Создайте файл с настройками

Выполните команду целиком — она создаст файл `.env` со всеми настройками:

```bash
cat > .env <<'EOF'
ENV=prod
TIMEZONE=Europe/Moscow
DATA_DIR=/app/data
DB_FILENAME=master.db

# Вуз-источник: spbpu (Политех) — рабочий путь на сегодня
UNIVERSITY=spbpu

# Сколько браузеров запускать одновременно.
# На сервере с 4 ГБ памяти больше 3 ставить нельзя — упадёт по памяти.
PARSER_PARALLELISM=3

# Токен для публикации данных — вставите на шаге 7
GITHUB_TOKEN=
EOF
```

Проверьте, что файл создался:

```bash
cat .env
```

> Токен пока пустой — это правильно, заполним его чуть позже.

---

## Шаг 6. Соберите программу на сервере

```bash
docker build -t masterchance:local .
```

Это самая долгая установка — **5–15 минут**. Побегут длинные строчки, в конце
должно появиться что-то со словами `naming to docker.io/library/masterchance:local`.

Проверка:

```bash
docker images | grep masterchance
```

Если строчка появилась — образ собран.

---

## Шаг 7. Получите ключ для публикации данных (токен GitHub)

Чтобы сервер мог сам выкладывать готовые данные на GitHub, ему нужен «пропуск».
Это делается **в браузере на вашем Mac**:

1. Откройте https://github.com/settings/tokens
2. Нажмите **`Generate new token`** → выберите **`Fine-grained token`**.
3. Заполните:
   - **Token name** — любое, например `masterchance-server`;
   - **Expiration** — срок жизни. Поставьте побольше (например 1 год), иначе
     через месяц всё перестанет публиковаться;
   - **Repository access** → **`Only select repositories`** → выберите
     **`masterchance_spbu`**;
   - **Permissions** → **`Repository permissions`** → найдите строку
     **`Contents`** и поставьте ей **`Read and write`**.
4. Внизу нажмите **`Generate token`**.
5. Появится длинная строка вида `github_pat_11ABC...`. **Скопируйте её сейчас** —
   второй раз GitHub её не покажет.

Теперь вернитесь в Терминал (вы на сервере) и впишите токен в настройки:

```bash
nano .env
```

Откроется простой редактор. Стрелками спуститесь к строке `GITHUB_TOKEN=` и
вставьте скопированный токен сразу после знака `=`, чтобы получилось:

```
GITHUB_TOKEN=github_pat_11ABC...
```

Сохраните: нажмите **Control + O**, затем **Enter**, затем **Control + X**.

---

## Шаг 8. Первый запуск — вручную

Теперь запустим весь цикл один раз и посмотрим, что всё работает:

```bash
set -a && . ./.env && set +a
scripts/server_update.sh
```

Первая строка загружает настройки из файла, вторая запускает обновление.

**Что вы увидите.** Строчки с временем и номером шага:

```
[2026-08-05 22:10:01] === Обновление данных начато ===
[2026-08-05 22:10:01] Шаг 1/3: скачиваем списки и считаем вероятности…
```

**Шаг 1 идёт долго — от 30 минут до нескольких часов.** Это нормально: сервер
открывает сотни страниц и потом гоняет 10 000 симуляций. Не закрывайте окно.

В конце должно появиться:

```
[2026-08-05 23:05:47] === Обновление завершено успешно ===
✅ Готово. Клиенты будут скачивать данные отсюда:
   https://github.com/Sheeshlove/masterchance_spbu/releases/download/data/master-snapshot.db.gz
```

> **Чтобы окно можно было закрыть**, запускайте так — тогда работа продолжится
> даже если у вас пропадёт интернет:
> ```bash
> apt install -y screen
> screen -S update
> set -a && . ./.env && set +a && scripts/server_update.sh
> ```
> Свернуть окно: **Control + A**, затем **D**. Вернуться позже: `screen -r update`.

---

## Шаг 9. Проверьте, что данные появились

Откройте в браузере на Mac:

```
https://github.com/Sheeshlove/masterchance_spbu/releases
```

Должен появиться релиз **«Данные для приложения»** с файлом
`master-snapshot.db.gz`. Если он там — **всё работает**: теперь приложение на
любом компьютере найдёт эти данные само.

Проверьте наверняка — запустите `MasterChance` на своём Mac. В серой строчке
должно появиться «Данные загружены: …», а по вашему коду — проценты.

---

## Шаг 10. Сделайте так, чтобы обновлялось само

Чтобы не запускать всё руками, поставим расписание. Выполните:

```bash
crontab -e
```

Если спросит, каким редактором пользоваться — выберите **nano** (обычно цифра `1`).

Спуститесь в самый низ и добавьте **одну строку**:

```
0 */6 * * * cd /root/masterchance_spbu && set -a && . ./.env && set +a && scripts/server_update.sh >> logs/cron.log 2>&1
```

Сохраните: **Control + O**, **Enter**, **Control + X**.

Эта строка означает: «каждые 6 часов зайди в папку проекта и обнови данные, а
всё, что напечатается, запиши в файл `logs/cron.log`».

Проверить, что расписание записалось:

```bash
crontab -l
```

Посмотреть, как прошло последнее автоматическое обновление:

```bash
tail -n 30 /root/masterchance_spbu/logs/cron.log
```

> Два обновления одновременно не запустятся: скрипт ставит блокировку. Если
> предыдущее ещё идёт, новое просто напишет «Предыдущее обновление ещё идёт» и
> завершится.

## Что делать, если что-то пошло не так

| Что вы видите | Что делать |
| --- | --- |
| `Permission denied (publickey,password)` при `ssh` | Неверный пароль или пользователь. Возьмите их из письма хостинга. |
| `docker: command not found` | Не выполнен шаг 3. |
| `Cannot connect to the Docker daemon` | Докер не запущен: `systemctl start docker` |
| Сборка образа падает на `pip install` | Обычно нехватка памяти. Возьмите тариф с 4 ГБ или добавьте подкачку: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile` |
| Шаг 1 падает, в логе `Killed` или `MemoryError` | Слишком много браузеров. Уменьшите в `.env`: `PARSER_PARALLELISM=2` |
| `❌ Не задан GITHUB_TOKEN` | Токен не подставился. Выполните `set -a && . ./.env && set +a` перед запуском (в cron это уже есть). |
| `❌ Не удалось создать релиз` | У токена нет права **Contents: Read and write**, либо истёк срок. Сделайте новый (шаг 7). |
| Данные собрались, но файла в Releases нет | Значит шаг 3 пропущен из-за пустого токена — в логе будет строка «Шаг 3/3 пропущен». |
| Приложение говорит «Не удалось скачать данные» | Проверьте, что файл виден по ссылке из шага 9 и репозиторий публичный. |
| Закончилось место на диске | `docker system prune -a` — удалит старые образы. |

## Коротко: что происходит после настройки

```
    СЕРВЕР (сам, каждые 6 часов)              АБИТУРИЕНТ
    ────────────────────────────              ──────────
    update_lists.py                           открывает MasterChance
      ├ скачивает списки вуза                 вводит свой код
      └ считает 10 000 симуляций                    │
    build_snapshot.py                               │
      └ упаковывает результат                       │
    publish_snapshot.sh                             ▼
      └ кладёт файл в GitHub  ──────────────►  видит свежие проценты
```

Ваш компьютер в этой схеме больше не участвует.
