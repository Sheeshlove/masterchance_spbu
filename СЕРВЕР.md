# Полная установка: сервер, сайт и приложение в Telegram

Инструкция от пустого сервера до работающего мини-приложения в Telegram.
Написана подробно: если вы никогда не открывали командную строку — просто
копируйте команды по одной, сверху вниз.

**Что получится в конце:**

| Что | Где | Что делает |
| --- | --- | --- |
| Обновлятор | на сервере, невидимо | раз в 3 часа тянет списки, считает шансы |
| Сайт | `https://masterchance-bot.ru` | вводишь код — видишь шансы |
| Mini App | внутри Telegram | тот же сайт, кнопкой в чате с ботом |
| Бот | в Telegram | отвечает на код текстом |
| Приложение для Mac | у пользователя | работает даже без интернета |

Всё это — один и тот же образ и одна и та же база. Считает данные **только
обновлятор**; сайт и бот их лишь показывают.

**Сколько времени займёт:** около часа, из которых 15 минут — ожидание сборки
и выпуска сертификата.

## Часть 0. Что понадобится

- **банковская карта** — сервер стоит примерно 300–700 ₽ в месяц, домен около
  200 ₽ в год;
- **аккаунт GitHub** — туда выкладываются готовые данные для Mac-приложения;
- **Telegram** — для бота;
- **ваш Mac** — только чтобы подключаться к серверу; после настройки он не нужен.

> **Источник данных — СПбГУ**, отчёт `enrollelists.spbu.ru`. Браузер для чтения
> не нужен, поэтому сервер требуется скромный.
>
> ℹ️ **Про даты экзаменов.** В отчёте СПбГУ есть только названия вступительных
> испытаний, без дат. Поэтому вместо расписания будет написано «Расписание
> экзамена пока не опубликовано». Баллы, шансы и проходные показываются как
> обычно.

## Часть 1. Сервер

### 1.1. Возьмите сервер

Подойдёт любой хостинг виртуальных серверов (VPS): Timeweb, Selectel, Beget,
aeza — порядок действий одинаковый.

При заказе выберите:

| Параметр | Что выбрать | Почему |
| --- | --- | --- |
| Операционная система | **Ubuntu 24.04** (или 22.04) | под неё написана инструкция |
| Оперативная память | **2 ГБ** | хватает: браузер не нужен |
| Процессор | 2 ядра | симуляции считаются быстрее |
| Диск | **от 10 ГБ** | образ занимает около 200 МБ |

После оплаты хостинг покажет три вещи — **запишите их**: IP-адрес сервера
(например `95.163.180.22`), имя пользователя (обычно `root`) и пароль.

### 1.2. Подключитесь к серверу

На своём Mac нажмите **⌘ + пробел**, наберите **Терминал**, Enter. Дальше:

```bash
ssh root@ВАШ_IP
```

- При первом подключении спросит `Are you sure you want to continue connecting?`
  — наберите **yes** и Enter.
- Спросит пароль. **Он не отображается — ни точками, ни звёздочками.** Это
  нормально, печатайте вслепую и жмите Enter.

Появилось `root@server:~#` — вы внутри. **Все следующие команды выполняются
здесь**, пока явно не сказано иное.

> Выйти с сервера — команда `exit`. Вернуться — снова `ssh root@ВАШ_IP`.

### 1.3. Установите Docker

Docker ставит Python и все библиотеки одним куском, чтобы не собирать их по
частям.

```bash
curl -fsSL https://get.docker.com | sh
```

Побегут строчки — ждите. Проверка:

```bash
docker --version
```

Ответило `Docker version 27.x` — идём дальше.

### 1.4. Скачайте проект

```bash
apt update && apt install -y git
git clone https://github.com/Sheeshlove/masterchance_spbu.git
cd masterchance_spbu
```

Проверка — команда `ls` должна показать `bot.py`, `web.py`, `README.md`.

> **Важно:** все дальнейшие команды выполняются **из этой папки**. Если
> вернулись на сервер позже — сначала `cd ~/masterchance_spbu`.

## Часть 2. Ключи и настройки

Понадобятся два ключа. Оба получаются **в браузере на вашем Mac**, а вписывать
их будем на сервере.

### 2.1. Токен бота (Telegram)

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`, придумайте имя и адрес бота (адрес должен
   заканчиваться на `bot`, например `masterchance_bot`).
3. BotFather пришлёт строку вида `123456789:AAE...` — это **токен**.

> 🔒 **Токен — это полный доступ к боту.** Кто его знает, тот может читать все
> сообщения пользователей и писать от имени бота. Не отправляйте его в чатах,
> не вставляйте в код и не показывайте на скриншотах. Если он куда-то утёк:
> @BotFather → `/mybots` → ваш бот → **API Token → Revoke current token**.

### 2.2. Токен GitHub (для публикации данных)

Нужен, чтобы сервер сам выкладывал готовые данные — их скачивает
Mac-приложение.

1. Откройте https://github.com/settings/tokens
2. **Generate new token** → **Fine-grained token**.
3. Заполните:
   - **Token name** — любое, например `masterchance-server`;
   - **Expiration** — поставьте побольше (год), иначе через месяц публикация
     перестанет работать;
   - **Repository access** → **Only select repositories** → `masterchance_spbu`;
   - **Permissions** → **Repository permissions** → строка **Contents** →
     **Read and write**.
4. **Generate token**. Появится строка `github_pat_11ABC...` — **скопируйте
   сейчас**, второй раз GitHub её не покажет.

### 2.3. Создайте файл настроек

Вернитесь в Терминал (вы на сервере, в папке проекта) и выполните команду
целиком, **подставив свои два токена**:

```bash
cat > .env <<'EOF'
ENV=prod
TIMEZONE=Europe/Moscow
DATA_DIR=/app/data
DB_FILENAME=master.db

# Источник данных (сейчас поддерживается только СПбГУ)
UNIVERSITY=spbgu

# Сколько списков тянуть одновременно. Это обычные запросы, не браузеры,
# так что 4 — вежливо к серверу вуза и достаточно быстро.
PARSER_PARALLELISM=4

# Токен бота из шага 2.1
BOT_TOKEN=СЮДА_ТОКЕН_БОТА

# Токен GitHub из шага 2.2
GITHUB_TOKEN=СЮДА_ТОКЕН_GITHUB

# Адрес сайта для Telegram Mini App. Пока оставьте закомментированным —
# включим в части 5, когда появится сертификат.
# WEBAPP_URL=https://masterchance-bot.ru
EOF
```

Впишите токены в файл:

```bash
nano .env
```

Откроется простой редактор. Стрелками дойдите до строк `BOT_TOKEN=` и
`GITHUB_TOKEN=`, замените заглушки на настоящие значения. Сохранить:
**Control + O**, Enter, **Control + X**.

Проверьте, что всё на месте (токены будут видны — это ваш сервер, всё в порядке):

```bash
cat .env
```

> Файл `.env` не попадает в репозиторий — он в `.gitignore`. Токены живут
> только здесь.

## Часть 3. Запуск

Одна команда собирает образ и поднимает всё: обновлятор, сайт и бота.

```bash
docker compose up -d --build
```

Первая сборка идёт **5–15 минут** — это самая долгая часть установки. Побегут
длинные строчки, в конце появятся три строки со словами `Started`.

Что запустилось:

| Сервис | Что делает |
| --- | --- |
| `updater` | сразу начинает первый сбор, дальше обновляет каждые 3 часа |
| `web` | сайт на `127.0.0.1:8080` (наружу пустим через nginx в части 4) |
| `bot` | Telegram-бот, уже отвечает на сообщения |

Терминал можно закрыть, Mac выключить — всё работает на сервере. После
перезагрузки сервера контейнеры поднимутся сами.

### Посмотреть, что происходит

```bash
docker compose logs -f updater
```

Первый проход занимает 20–40 минут: скачивание списков → 10 000 симуляций →
публикация. В конце появится строка **«Следующее обновление примерно в …»**.

Выйти из просмотра логов — **Control + C** (это закроет просмотр, а не сам
обновлятор).

### Полезные команды

```bash
docker compose ps                  # кто сейчас работает
docker compose logs -f web         # логи сайта
docker compose logs -f bot         # логи бота
docker compose restart bot         # перезапустить один сервис
docker compose down                # остановить всё
docker compose up -d               # включить снова
```

> Если раньше вы запускали обновлятор старой командой `docker run --name
> masterchance-updater`, удалите его — иначе будут работать два сразу:
> `docker rm -f masterchance-updater`

## Часть 4. Домен и HTTPS

Без этого шага сайт доступен только внутри сервера, а Mini App не заработает
вовсе: **Telegram открывает мини-приложения только по `https://` с настоящим
сертификатом**. По `http://` и по голому IP — не откроет, причём молча.

### 4.1. Пропишите A-запись

Это единственное, что нельзя сделать командой. Узнайте IP сервера:

```bash
curl https://api.ipify.org
```

В панели регистратора, где куплен домен, добавьте две записи:

| Имя/Хост | Тип | Значение |
| --- | --- | --- |
| `@` (или пусто) | `A` | IP сервера |
| `www` | `A` | IP сервера |

Изменение расходится по интернету от нескольких минут до пары часов. Проверить
**со своего Mac** (в новом окне Терминала, не на сервере):

```bash
dig +short masterchance-bot.ru
```

Команда молчит — ждите. Показала IP сервера — идите дальше.

### 4.2. Выпустите сертификат

Одна команда: проверит A-запись, поставит nginx и certbot, включит конфиг и
выпустит сертификат.

```bash
sudo bash scripts/setup_https.sh
```

Скрипт останавливается с понятным сообщением, если домен ещё не доехал или
указывает не на этот сервер. Это самая частая причина, по которой выпуск
сертификата не удаётся, поэтому проверка стоит раньше всего остального.

Готово, когда `https://masterchance-bot.ru` открывается в браузере с замочком.

> Сертификат продлевается сам — certbot ставит для этого системный таймер.

## Часть 5. Приложение в Telegram

### 5.1. Скажите проекту адрес сайта

```bash
nano .env
```

Найдите строку `# WEBAPP_URL=...`, **уберите `#` в начале**:

```
WEBAPP_URL=https://masterchance-bot.ru
```

Сохраните (**Control + O**, Enter, **Control + X**) и перезапустите бота:

```bash
docker compose up -d --build bot
docker compose logs bot | tail -20
```

В логах должно появиться **«Mini App подключён»**.

> Если адрес не задан или начинается с `http://`, бот просто работает как
> обычный бот, без кнопки. Это не ошибка, а защита: на `http`-адресе Telegram
> отклонил бы запрос и бот упал бы при старте.

### 5.2. Пропишите Mini App у @BotFather

1. [@BotFather](https://t.me/BotFather) → `/mybots` → ваш бот.
2. **Bot Settings → Menu Button → Configure menu button**.
3. Пришлите адрес `https://masterchance-bot.ru`.
4. Пришлите название кнопки, например `Открыть приложение`.

### 5.3. Необязательное, но приятное

Там же, в **Bot Settings**, можно задать описание бота и картинку — это то, что
человек видит до первого сообщения.

## Часть 6. Проверка, что всё работает

Пройдите по списку — каждая строка проверяет свой кусок.

| Что проверяем | Как | Что должно быть |
| --- | --- | --- |
| Сайт жив | открыть `https://masterchance-bot.ru` | форма ввода кода, замочек в адресной строке |
| Данные посчитаны | ввести реальный код абитуриента | направления и проценты |
| Объяснения | нажать «Почему такой шанс?» | раскрывается расклад по местам и баллам |
| Страницы | открыть «Как всё устроено» | текст про механику |
| Бот | `/start` в чате с ботом | приветствие и кнопка «Открыть приложение» |
| Mini App | нажать кнопку в чате | сайт открывается **внутри** Telegram |
| Кнопка меню | слева от поля ввода в чате | открывает то же приложение |
| Публикация данных | `docker compose logs updater \| grep -i snapshot` | строка про успешную выгрузку |

Проверка сервера одной командой:

```bash
curl -s -o /dev/null -w "сайт: %{http_code}\n" https://masterchance-bot.ru/healthz
docker compose ps
```

Должно быть `сайт: 200` и три сервиса в состоянии `Up`.

## Часть 7. Обслуживание

### Обновить проект

Сервер сам за репозиторием не следит. После изменений в проекте:

```bash
cd ~/masterchance_spbu
git pull
docker compose up -d --build
```

Это безопасно: `.env`, база в `data/` и снапшоты в `dist/` не отслеживаются
гитом, поэтому `git pull` их не тронет.

> Забыть про этот шаг — самая частая причина странных ошибок вида «файл не
> найден» или «нет такого модуля»: контейнер работает со старой версией кода.

### Что происходит само

- каждые 3 часа — сбор списков, пересчёт, публикация;
- при перезагрузке сервера — контейнеры поднимаются сами;
- раз в ~60 дней — certbot продлевает сертификат.

От вас не требуется ничего. Разумно раз в пару недель заглядывать в
`docker compose logs --tail 50 updater`.

### Сменить токен бота

Если токен утёк: @BotFather → `/mybots` → бот → **API Token → Revoke current
token**. Новый впишите в `.env` (`nano .env`) и выполните
`docker compose up -d bot`.

### Место на диске

Диск забивается быстрее, чем кажется, и почти всегда по одной причине: **каждая
пересборка оставляет предыдущий образ висеть**, а кэш сборки Docker растёт до
гигабайтов. Плюс логи контейнеров, которые Docker сам по себе не подрезает
никогда.

Уборка одной командой:

```bash
sudo bash scripts/cleanup.sh
```

Скрипт покажет, сколько было и сколько стало. Он убирает остановленные
контейнеры, висячие образы, кэш сборки, разросшиеся логи, кэш apt, старые
журналы systemd и логи certbot. **Базу `data/`, снапшот `dist/` и работающие
контейнеры не трогает.**

Если места всё равно мало — есть режим пожёстче: он удалит вообще все образы,
которые не заняты запущенными контейнерами (следующая сборка будет дольше,
кэш соберётся заново):

```bash
sudo bash scripts/cleanup.sh --deep
```

Посмотреть, что занимает место:

```bash
df -h /
du -h -d1 / 2>/dev/null | sort -h | tail -15
```

> **Про логи.** В `docker-compose.yml` задан предел 10 МБ × 3 файла на сервис.
> Он применяется только при **пересоздании** контейнера, поэтому один раз
> выполните `docker compose up -d` — после этого логи расти перестанут.

## Если что-то пошло не так

| Что видите | Что делать |
| --- | --- |
| `Permission denied (publickey,password)` при `ssh` | Неверный пароль или пользователь. Возьмите их из письма хостинга. |
| `docker: command not found` | Не выполнен шаг 1.3. |
| `Cannot connect to the Docker daemon` | Докер не запущен: `systemctl start docker` |
| `python: can't open file '/app/…py'` | Образ собран из старой версии кода: `git pull && docker compose up -d --build` |
| `ModuleNotFoundError: No module named '…'` | То же самое — пересоберите образ. |
| Скрипт HTTPS пишет «домен указывает на …» | A-запись ещё не доехала или ведёт не туда. Проверьте `dig +short masterchance-bot.ru`. |
| `https://` не открывается, `http://` работает | Сертификат не выпущен: повторите `sudo bash scripts/setup_https.sh` |
| Кнопки Mini App нет в боте | `WEBAPP_URL` не задан, задан с `http://`, или бот не перезапущен после правки `.env`. |
| Mini App открывается пустым | Сайт не отвечает: `docker compose logs web`. |
| Приложение отвечает «Заявок не найдено» на любой код | В базе нет заявок — источник вернул пустые списки. Диагностика: `docker compose run --rm updater scripts/diagnose_spbgu.py` |
| Первый проход идёт больше часа | Нормально для слабого сервера. Смотрите логи: считаются 10 000 симуляций. |
| Закончилось место на диске | `docker system prune -a` |

Если ничего не помогло — напишите на `Egorsheeshwork@yandex.ru`, приложив вывод
`docker compose logs --tail 100`.
